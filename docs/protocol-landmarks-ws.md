# Протокол резервного режиму: WebSocket `/ws/landmarks`

Резервний режим вмикається, коли браузер не встигає обробляти кадри локально
(частота обробки нижча за 25 кадр/с протягом інтервалу усереднення) і користувач погодився перейти в нього.
Клієнт надсилає стиснуті кадри, сервер повертає 21 ключову точку кисті.
Кадри не зберігаються ні на клієнті, ні на сервері.

Реалізація клієнта: `frontend/src/services/landmarks_socket.ts`.
Mock-сервер для розробки: `frontend/scripts/mock-landmarks-ws.ts`.

## З'єднання

- Адреса: `wss://<host>/ws/landmarks` (у розробці `ws://localhost:5173/ws/landmarks` через проксі Vite).
  Базову адресу можна перевизначити змінною `VITE_WS_BASE_URL`.
- Одне з'єднання на сеанс вправ, підпротоколи не використовуються.
- `binaryType = arraybuffer`.

### Автентифікація

Першим повідомленням після відкриття клієнт надсилає текстовий кадр:

```json
{ "type": "auth", "token": "<JWT access token або null>" }
```

Маркер той самий, що для REST (`Authorization: Bearer …`). Спосіб передавання маркера зосереджено
в одній функції `authenticateSocket()`. Якщо бекенд обере query-параметр (`?token=…`), змінюється лише вона.

Сервер має перевірити маркер до обробки першого кадру. Якщо маркер недійсний, сервер надсилає помилку
(див. нижче) і закриває з'єднання з кодом `4401`.

## Кадр: клієнт → сервер (бінарне повідомлення)

| Зсув, байт | Тип | Поле | Опис |
|---|---|---|---|
| 0 | `uint32` LE | `seq` | порядковий номер кадру в з'єднанні, від 1 |
| 4 | `float64` LE | `timestamp` | `performance.now()` моменту захоплення кадру, мс |
| 12 | `uint16` LE | `width` | ширина **вихідного** кадру вебкамери, пікс. |
| 14 | `uint16` LE | `height` | висота вихідного кадру, пікс. |
| 16 | байти | — | зображення WebP (типово) або JPEG |

- Зображення зменшене до короткої сторони 256 пікс. зі збереженням пропорцій. Розмір задає `remote.shortSide` у `src/config/tracking.ts`.
- Кадр **не дзеркальний**, як і в локальному режимі.
- Клієнт не надсилає наступний кадр, доки не отримає відповідь на попередній, тож у дорозі одночасно не більше одного кадру.
  Якщо відповідь не прийшла за 2 с (`remote.responseTimeoutMs`), кадр вважається втраченим.

## Відповідь: сервер → клієнт (текстове повідомлення JSON)

```json
{
  "seq": 42,
  "timestamp": 123456.789,
  "handedness": "Left",
  "landmarks": [[0.51, 0.72, 0.0], [0.48, 0.66, -0.012], "… усього 21 трійка [x, y, z]"]
}
```

| Поле | Тип | Опис |
|---|---|---|
| `seq` | number | `seq` кадру, на який це відповідь |
| `timestamp` | number | **без змін** той `timestamp`, що прийшов у заголовку кадру. Фільтр 1€ бере з нього справжній інтервал між кадрами |
| `handedness` | `"Left"` \| `"Right"` \| `null` | мітка руки MediaPipe **як є**, без виправлення. Клієнт виправляє її так само, як у локальному режимі |
| `landmarks` | `[number, number, number][21]` \| `null` | нормовані координати MediaPipe (x, y у частках ширини/висоти кадру, z відносно зап'ястка). `null`, якщо кисть не виявлено |

Сервер шукає **одну** кисть (`num_hands = 1`), впевненість виявлення і відстеження 0,5.
Відповідь на кадр без кисті обов'язкова (`landmarks: null`), бо клієнт за нею рахує частку кадрів з кистю.

## Помилки: сервер → клієнт

```json
{ "type": "error", "code": "unauthorized", "message": "Потрібна автентифікація." }
```

| `code` | Коли | Дія сервера |
|---|---|---|
| `unauthorized` | маркер відсутній або недійсний | закрити з'єднання, код `4401` |
| `rate_limited` | клієнт перевищив ліміт кадрів за секунду | відкинути кадр (відповідь на нього не надсилати) |
| `bad_frame` | заголовок або зображення не розбираються | відповісти `landmarks: null` або помилкою |
| `unavailable` | сервіс розпізнавання (gRPC) недоступний | закрити з'єднання, код `1011` |

Повідомлення `message` українською: клієнт показує його користувачеві.
Коли з'єднання закривається, клієнт повертається до локального режиму.

## Вимоги до сервера

- Лише TLS (`wss`) у робочому середовищі.
- Зображення обробляються в пам'яті й не записуються на диск чи в журнали.
- Ліміт частоти кадрів від одного клієнта (наприклад, 30 кадр/с).
- Сервер застосунку пересилає кадр сервісу розпізнавання через gRPC і повертає результат клієнту.

## Розробка без бекенду

```sh
cd frontend
npm run mock:ws -- --port 8090 --delay 30             # синтетична кисть
npm run mock:ws -- --file hand-recording-….json       # запис, зроблений з ?record=1
VITE_WS_PROXY_TARGET=http://localhost:8090 npm run dev
```
