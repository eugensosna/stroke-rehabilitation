# Задача 1. Джерело ключових точок кисті і резервний режим

## Контекст

Зараз `src/composables/useHandTracking.ts` використовує застарілий пакет `@mediapipe/hands`,
шукає до двох кистей (`maxNumHands = 2`), передає моделі дзеркальний кадр (`selfieMode: true`)
і віддає назовні лише точку 0 (зап'ясток). У роботі зафіксовано інше:

- MediaPipe Hand Landmarker (`@mediapipe/tasks-vision`, WASM), **одна** кисть, впевненість виявлення і відстеження 0,5;
- моделі передається кадр **без** відображення, дзеркалиться лише зображення на екрані (CSS), бо дзеркальний кадр інвертує ознаку лівої/правої руки;
- кадри подаються в циклі `requestAnimationFrame`; поки модель зайнята, кадр пропускається (лістинг «Цикл передавання кадрів» у розділі 3 — зберегти цю логіку);
- фактична частота обробки обчислюється за часовими мітками оброблених кадрів;
- якщо частота нижча за 25 кадр/с протягом інтервалу усереднення, клієнт **пропонує** резервний режим: кадр зменшується, стискається в JPEG/WebP і надсилається на сервер через WebSocket, сервер повертає 21 ключову точку.

## Мета

Один composable-джерело ключових точок, яке однаково віддає кадри з локального і з серверного розпізнавання,
щоб подальша обробка (задачі 2–3) не знала, звідки прийшли дані.

## Що зробити

1. Замінити `@mediapipe/hands`, `@mediapipe/camera_utils`, `@mediapipe/pose`, `@tensorflow-models/pose-detection` на `@mediapipe/tasks-vision`. Модель і WASM завантажувати з закріпленої версії (не `latest`).
2. Описати тип у `src/types/landmarks.ts`:
   ```ts
   interface HandFrame {
     landmarks: { x: number; y: number; z: number }[] // 21 точка, нормовані координати MediaPipe
     handedness: 'Left' | 'Right'
     width: number; height: number                    // W, H кадру в пікселях (для формули ізотропних координат)
     timestamp: number                                 // performance.now() моменту захоплення кадру, мс
     source: 'local' | 'remote'
   }
   ```
   Кадр без виявленої кисті теж передається (`landmarks: null`), щоб рахувати частку кадрів з кистю.
3. `useHandLandmarks(videoRef, options)` → `{ start, stop, mode, fps, detectionRate, lastFrame, error, onFrame(cb) }`.
   - `fps` — ковзне середнє за останні N секунд (N у конфігурації, типово 2 с).
   - `detectionRate` — частка кадрів з кистю за той самий інтервал.
   - `mode: 'local' | 'remote'`; подія `lowFps`, коли `fps < 25` довше за інтервал усереднення. Перемикання лише після згоди користувача (діалог у задачі 4), не автоматично.
4. Резервний режим (`src/services/landmarks_socket.ts`):
   - `wss://<host>/ws/landmarks`, маркер доступу передається при встановленні з'єднання (query-параметр або перше повідомлення — винести в одну функцію, бо бекенд ще не реалізовано);
   - кадр зменшується до короткої сторони 256 px (конфігурується), кодується `canvas.toBlob('image/webp' | 'image/jpeg', q)`; у дорозі одночасно не більше одного кадру;
   - відповідь сервера: JSON `{ seq, timestamp, handedness, landmarks: [[x,y,z]×21] | null }`; `timestamp` — той, що клієнт надіслав разом із кадром, щоб фільтр 1€ брав справжній інтервал між кадрами;
   - описати протокол у `docs/protocol-landmarks-ws.md`, щоб за ним реалізувати бекенд;
   - для розробки — mock-сервер (`scripts/mock-landmarks-ws.ts` або режим у Vite), що повертає записані кадри.
5. Утиліта `drawHandSkeleton(ctx, frame, { mirrored })` для мініатюри камери з накладеним скелетом кисті.
6. Режим запису для експерименту (лише dev, вмикається параметром `?record=1`): кнопка «Зберегти запис» вивантажує JSON з усіма `HandFrame` сеансу. Без зображень. Потрібно для підбору параметрів фільтра і вимірювання частоти в розділі 3.
7. Перевести `GameArcade1.vue` і `ArkanoidGame.vue` на новий composable (беруть `landmarks[0]`), щоб вони не зламалися.

## Критерії приймання

- В інтерфейсі відео дзеркальне, а `handedness` для правої руки пацієнта — `Right`.
- Показується одна кисть, навіть якщо в кадрі дві.
- На ноутбуці `fps` і `detectionRate` відображаються в dev-панелі й відповідають очікуванням (кисть сховано → `detectionRate` падає до 0).
- З mock-сервером резервний режим віддає кадри з `source: 'remote'`, без накопичення черги.
- Старих пакетів MediaPipe немає в `package.json`.
