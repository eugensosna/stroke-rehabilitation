# Задача 3. Рушій вправи: автомат станів, серія, калібрування, обмін із сервером

Залежить від задач 1 і 2.

## Контекст

Розділ 2 роботи (підрозділи «Скінченний автомат вправи», «Адаптація складності вправ»,
«Показники сеансу для фахівця», «Калібрування») описує спільну логіку для всіх вправ.
Ігри (задача 4) мають отримувати від неї лише нормований показник `u` і події, не працюючи з ключовими точками.

## Що зробити

### 3.1. Скінченний автомат (`src/model/exerciseFsm.ts`, без Vue)

- Стани: `Waiting` («Очікування»), `Moving` («Рух»), `Holding` («Утримання»), `Returning` («Повернення»), `Paused` («Пауза»).
- Вхід на кожен кадр: `{ t, u, handPresent, isolationOk? }`.
- Переходи:
  - `Waiting → Moving`, коли `u > thetaR` (момент `t_s`);
  - `Moving → Holding`, коли `u ≥ thetaG` і (для ізольованих рухів) `I_k ≥ Imin_k` (момент `t_m`);
  - `Holding → Moving`, коли `u < thetaG − h` (гістерезис);
  - у `Holding` при `τ ≥ tHold` — спроба успішна → `Returning`;
  - у `Moving`, якщо від `t_s` минуло `tMax` — спроба невдала → `Returning`;
  - `Returning → Waiting`, коли `u ≤ thetaR` (момент `t_e`), повторення завершене;
  - кисті немає довше `tLost` з будь-якого стану → `Paused`, поточна спроба скасовується; повернення кисті → `Waiting`.
- Події: `moveStart`, `goalReached`, `goalLost`, `success`, `fail`, `repetitionEnd`, `paused`, `resumed`.
- Для кожного повторення зберігається запис: `t_s`, `t_m | null`, `t_e`, результат, рівень, значення керуючого показника за кадрами (для `A_m`), для ізольованих рухів — `Φ_j` усіх пальців (для `I_k`), чи була пауза.
- Тести з синтетичними послідовностями `u`: шум біля порога без гістерезису не дає подвійних зарахувань; тайм-аут; пауза; ізольованість блокує утримання.

### 3.2. Опис вправ (`src/exercises/definitions.ts`)

Чотири вправи з табл. 2.1 роботи:

| id | Керуючий показник | Напрям | Додаткова умова |
|---|---|---|---|
| `pinch` | `d_2` | спадний | — |
| `opposition` | `d_k`, k задає гра | спадний | `d_k` заданого пальця — найменша серед `d_2..d_5` |
| `openClose` | `O` | зростаючий | — |
| `isolatedFinger` | `Φ_k`, k задає гра | зростаючий | `I_k ≥ Imin_k` |

### 3.3. Композиційна функція `useExercise(definition, calibration, settings)`

Поєднує джерело кадрів (задача 1) → `handFilter` → `computeFrameMetrics` → `u` → автомат → адаптація рівня.
Повертає реактивні `u`, `state`, `level`, `repetitions`, `score`, `hint` і шину подій.
Підказки: кисть поза кадром; кисть повернуто ребром до камери (відношення площі/ширини долоні в площині зображення до `s` нижче порогу — критерій винести в конфігурацію); недоступна вправа через малий діапазон калібрування; пропозиція перепочити, якщо в серії помітно знижуються частка успішних спроб і середня амплітуда.

### 3.4. Калібрування (`useCalibration`)

- Кроки за підрозділом «Калібрування» роботи: вихідне положення; максимальне розкриття і кулак; щипковий захват; дотик великим пальцем до кожного пальця; згинання кожного пальця окремо.
- Кожен крок: підготовка (3 с, відлік) → запис (конфігурується, типово 5 с) → результат `{ xr, xg, unavailable }` для відповідних показників.
- Скорочене калібрування на початку наступного сеансу: лише вихідне положення і максимальний рух для обраних вправ; діапазон оновлюється з урахуванням найбільших амплітуд попереднього сеансу.

### 3.5. Агрегування серії і обмін із сервером

- `buildSeriesReport(repetitions, …)` → запис за табл. 2.2: `N`, `N_s`, `N_s/N`, `Ā`, `A_max` (градуси або частки `s`), `f`, `V`, `t̄_h`, `Ī_k`, `x_r`, `x_g`, `L` початковий і кінцевий, тривалість активної роботи, частка кадрів з кистю, режим обробки, середня частота обробки. Плюс деталізація повторень (кути суглобів для аналізу фахівцем).
- Типи і сервіси в `src/types/exercise.ts`, `src/services/exercise_service.ts`, `src/services/calibration_service.ts`. Бекенд ще не має цих ресурсів, тому:
  - запропонувати контракт: `POST /api/exercise-series`, `GET /api/exercise-series/my`, `GET/POST /api/calibrations/latest`, `GET /api/exercise-settings/my`; описати JSON у `docs/api-exercise.md`;
  - додати mock-адаптер для axios за прапорцем `VITE_USE_MOCKS=true`, щоб фронтенд працював без бекенду.
- `useGameSession` лишити для старих ігор, нові вправи зберігаються через новий сервіс.

## Критерії приймання

- Повний ланцюжок працює на записаному JSON-сеансі із задачі 1 (тест або dev-сторінка «Відтворити запис»): видає ті самі повторення і показники при кожному запуску.
- Звіт серії містить усі поля табл. 2.2; при `M < 3` `f` і `V` = `null`.
- На сервер не передаються координати ключових точок, лише числові показники.
